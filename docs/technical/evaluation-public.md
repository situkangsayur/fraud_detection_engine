# Detection quality on public datasets — end-to-end evaluation

Runs: 2026-10-07/08, separate evaluation stack (`fraud-eval`, same images as the live stack), tool
`tools/public_eval` (branch `eval/public-datasets`). Every number below comes from decisions the platform stored after
ingesting the data through its public API (mapping → features → graph → ML → rules → noisy-OR); ground truth is joined
afterwards from a local file that is never sent to the platform. This complements the synthetic simulator run in
`evaluation.md`.

## 1. Datasets and sampling

| Dataset | Real / synthetic | Licence | Events (per seed) | Fraud in scored 30 % | Platform fields used |
|---|---|---|---|---|---|
| IBM TabFormer card transactions (Padhi et al. 2021) | synthetic | Apache-2.0 | ~80,000 (4-month window with most fraud, 2015-10…2016-01) | 150–183 | customer, card (hashed), merchant, MCC, city, chip/online, error codes (`source.errors`) |
| Fraud_Data e-commerce (public 120k copy) | unknown, likely synthetic | **unknown — internal test only** | 120,000 (all) | 1,647 | customer, sign-up time, device, IP (+ IP country) |
| IBM AMLworld HI-Small (Altman et al. 2023) | synthetic | CDLA-Sharing-1.0 | ~80,000 (laundering senders ≤ 500 tx up to half, then random senders) | 1,382–1,506 | sender = customer, recipient account → bank-account entity, amount, payment format |
| RBA login (Wiefling et al. 2022) | synthesized from real SSO logs | CC BY 4.0 | ~84,000 (all 138 ATO users + random users; window ends 3 days after last ATO label) | 38 | user, IP, country, city, device (type, OS, browser), user agent, login success |
| ULB credit card (Dal Pozzolo et al. 2015) | real (PCA) | DbCL v1.0 | 60,492 (all 492 fraud + 60,000 legit) | 109 | ML-only: V1–V28 + amount as `extra_source_fields`; no entity ids |

Three seeds per dataset vary the user/account sample (TabFormer, AMLworld, RBA) and the label plan (all).

## 2. Protocol

1. One project per dataset × configuration × seed in tenant `public-eval`; separate **analyst** and **approver** users.
2. First 70 % of events (chronological, by count) ingested `load_only`.
3. Delayed, partial labels: 60 % of fraud older than min(7 days, 20 % of the history span), 3 % of legit; customers of
   labelled fraud marked fraud with p = 0.7 (graph proximity). Supervised label maturity = age of the last history event
   + label delay, capped at 14 days.
4. `mlp_backprop` (supervised) and `isolation_forest` + `hdbscan` (unsupervised) trained by the analyst and approved by
   the approver (maker–checker).
5. Remaining 30 % ingested with `mode=score`; default thresholds (review ≥ 50, decline ≥ 80), noisy-OR fusion.
6. **Evaluation-only engine timeouts** (ML 3 s, graph 2 s, rules 5 s instead of 100/200/300 ms) because several projects
   and model training ran in parallel on one host; with production budgets most early decisions were degraded for load
   reasons. Degraded share in the final runs: 0.1–0.3 % of decisions; metrics on non-degraded events only are within
   0.006 AUC of the full set (reported in the JSON).

Configurations: **tpl** = the platform's stage-template rules (card → `pre_payment`, e-commerce → `promo`, AMLworld →
`payout`, RBA → `account_security`); **lit** = template `none` + ruleset `RS-LIT` built from the literature rule catalogue
(R01–R40; rule code `RL-LIT-Rxx`, source in the description, catalogue thresholds [S] or example placeholders [P], not
tuned on the test window, approved by the approver); **ml** = no rules (ULB).

LIT rules per dataset — TabFormer: R01, R02, R03 (TabFormer error codes), R04, R05, R08 (merchant city as location proxy),
R09 (PSD2 ETV 500), R10a/b/c (PSD2 Art. 16 30/100/5), R11, R12 (night-time proxy). E-commerce: R31a/b (accounts per
device/IP, 1 day ≥ 3), R32a/b (graph shared entity / component ≥ 5), R20a (< 1 s sign-up → purchase), R20b (< 1 h, [P]),
R11. AMLworld: R36, R37, R39, R40, R40b, R11. RBA: R14 (≥ 5 failed logins, PSD2 Art. 4(3)(b)), R15, R16, R16b. Omitted
for lack of inputs: TabFormer R06/R07/R13; e-commerce R07/R33; AMLworld R26/R38; RBA R18 (no external IP list — the
dataset's `Is Attack IP` is label-like and was not used) and R11 (no amounts).

## 4. Reading the results

* **The fused score ranks well where the data carries behavioural signal.** AUC 0.914–0.919 on TabFormer, 0.957–0.958
  on AMLworld, 0.877–0.884 on RBA and 0.956 on ULB. On every dataset the fused AUC is within 0.02 of the best single
  engine or above it; on RBA it is 0.05 above the best single engine (supervised 0.81–0.83), the clearest case of engines
  complementing each other.
* **The graph engine contributes where identities are shared across customers.** RBA (shared IPs/devices between the
  attacker sessions and other accounts): graph AUC 0.71–0.74 from a cold start, with only partial customer labels.
  AMLworld: 0.53 — recipients are bank-account entities and confirmed launderers are few, so distance-to-fraud rarely
  applies within 2 hops in a 30 % window. TabFormer and ULB have no cross-customer identifiers (one card per user /
  no ids), so the graph engine is 0.50 by construction.
* **Rules engine: literature rules > stage templates as a ranking signal.** Rules-engine AUC rose from 0.66 → 0.70
  (TabFormer), 0.50 → 0.61 (e-commerce), 0.50 → 0.65 (AMLworld) and 0.50 → 0.73 (RBA). The stage templates were written
  for the platform's canonical marketplace events (promo codes, cashback, recipients, credential changes) and mostly do
  not fire on these schemas. The fused AUC barely changes between configurations (≤ 0.007), because the supervised and
  anomaly models dominate the ranking; the LIT rules matter more for recall at the default threshold (TabFormer
  91 → 96 %, RBA 93 → 97 %) and, above all, for explanation: every LIT hit cites a regulation or paper.
* **Generic regulatory gates are poor detectors on their own.** PSD2 low-value limits (R10a/b/c) and the
  night-time proxy (R12) match thousands of TabFormer transactions with ~1 % precision and push the default-threshold FPR
  from 23 % to 44 %. They describe when strong authentication is required, not fraud; in production they belong in shadow
  mode or at low weight. The behavioural rules are precise: R11 (amount z-score) 9 %, R03 (card-testing error codes) 6 %,
  R09 (> ETV 500) 8 % on a 0.7 % base rate; AMLworld R39 (new account, high value) 16 % and R11 27 % on a 6 % base rate;
  RBA R16 (new device + unusual country) 7.8 % on a 0.15 % base rate (50× lift).
* **Thresholds must be calibrated per project** — the same lesson as the simulator run, now on public data. At the
  default 50 the FPR ranges from 9 % (ULB) to 53 % (AMLworld); at FPR ≤ 5 % the recall is 64 % (TabFormer), 83 %
  (AMLworld), 60–63 % (RBA) and 88 % (ULB). Precision at that operating point follows the base rate: 51 % on AMLworld
  (6 % fraud in the sample), 8–10 % on card data, 2 % on RBA logins (0.15 % fraud).
* **E-commerce (Fraud_Data) is hard under a chronological split.** All 6,021 frauds with a 1-second sign-up→purchase
  gap (the dataset's well-known easy pattern, which also carries the shared-device rings) occur in its first weeks and
  fall entirely in the history window. The scored 30 % has one purchase per user and no velocity history, so the
  fused AUC is 0.61 and R20a/R31 never fire. A random split would look far better and would be misleading.
* **AMLworld laundering patterns** are all recalled at ≥ 98 % at the default threshold (fan-in, fan-out, cycle,
  scatter-gather, gather-scatter, bipartite, stack, random), but at 50 % FPR; the useful operating point is the
  calibrated one (83 % recall at 5 % FPR).

## 5. Caveats

* Four of five datasets are synthetic (TabFormer, AMLworld; RBA is synthesized from real logs; Fraud_Data of unknown
  origin). Only ULB is real, and it has no entity identifiers, so it tests only the ML engines.
* Samples are stratified (fraud users/accounts over-represented in TabFormer and AMLworld, all ATO users in RBA, all
  ULB frauds), so absolute precision is higher than at natural prevalence; AUC is prevalence-independent.
* Engine timeouts were raised for evaluation (see §2); latency was not evaluated here.
* Runs interrupted during label posting were resumed without re-posting (e-commerce seed 1 has 3.4–4.6k labels
  instead of ~12k); timestamps were shifted at preparation time, and training ran hours later, so the effective
  supervised training set of the short ULB dataset differs between seeds (3.8k–25.6k rows). Both are visible in the
  JSON (`labels`, `models.supervised.metrics.train`).
* Fraud_Data's licence is unknown: use the e-commerce numbers internally only.

## 6. Reproduce

```bash
~/datasets/fraud-public/download.sh
cd tools/public_eval
for s in 1 2 3; do for d in tabformer ecom aml rba; do for c in tpl lit; do
  python -m public_eval run $d --seed $s --config $c; done; done; python -m public_eval run ulb --seed $s --config ml; done
python -m public_eval.aggregate
```
